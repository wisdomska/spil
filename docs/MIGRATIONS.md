# Migrations

Database changes made for the fix handoff (docs/SPIL_Fix_Handoff.md). Supabase CLI migrations
only run forward, so every migration has an undo script in `supabase/rollbacks/`. To undo one:
run its rollback script against the database, then mark the migration reverted so the CLI stops
counting it:

```bash
supabase migration repair --status reverted <version>
```

Apply order: staging first (`supabase db push` while linked to `cambebifktqgnbthumzq`), then
production when the release goes to `main`.

RLS: `players.age_band` is not in the column grants, so clients can neither read nor write it (pgTAP `07_age_bands_test.sql`); only the API writes it. Seed: adult packs get `min_age` 18.

SPIL-11: clients cannot update `rooms` (pgTAP `11_reveal_pacing_test.sql` checks `reveal_index`); only the host's API call moves the reveal.

SPIL-09: the new guess columns follow the existing `guesses` policies (a player reads their own guesses, everyone in the room after the reveal); pgTAP `10_guess_points_test.sql`.

SPIL-05: `captcha_events` has RLS and no grants for anon or authenticated (pgTAP `09_captcha_events_test.sql`).

SPIL-08: packs and questions keep their existing RLS (admin writes by role, public reads of live content); pgTAP `08_pack_sections_test.sql`; the seed sets sections, spice and 10 questions per game.

SPIL-03 RLS: the new columns sit on `players`, which already has row level security; members read them
through the existing policies. pgTAP: `supabase/tests/06_answer_progress_test.sql`. Seed: no
change needed (the columns have defaults).

Game modes RLS: `mode_inputs` has row level security; a player reads their own rows, and every member reads the room's rows once it is revealed. Writes go through `save_mode_inputs` (service role). pgTAP: `supabase/tests/13_game_modes_test.sql`.

Hot Takes: no new table; packs and questions keep their RLS. pgTAP: `supabase/tests/14_hot_takes_test.sql`; `00_schema_test.sql` lists Hot Takes among the live packs.

Most Likely To: no new table; votes are `mode_inputs` rows of kind `vote` under the existing RLS (a player reads only their own until the reveal; the reveal state sends counts, never who voted for whom). pgTAP: `supabase/tests/15_most_likely_test.sql`.

Red Flag, Green Flag: no new table or function; swipes are ordinary answers under the existing RLS. pgTAP: `supabase/tests/16_red_green_test.sql`.

Rank the Room: no new table or content; rankings are `mode_inputs` rows under the existing RLS, and the reveal state carries only the room's order. pgTAP: `supabase/tests/17_rank_room_test.sql`.

Imposter RLS: `imposters` has row level security with one policy, `imposters_select_revealed` (members of a revealed room); anon has no access and players cannot write it (the API writes it with the service role at start). The imposter is never told and cannot look themselves up. pgTAP: `supabase/tests/18_imposter_test.sql`; `00_schema_test.sql` lists the new table and pack.

Two Truths: no new table; cards and spots are `mode_inputs` rows under the existing RLS. pgTAP: `supabase/tests/19_two_truths_test.sql`.

Who Said That? RLS: `text_guesses` has row level security with `text_guesses_select_own` and `text_guesses_select_revealed`; anon has no access and players cannot write it (the API does). Written answers are `mode_inputs` rows of kind `text` under the existing RLS (own rows, everyone's after the reveal). pgTAP: `supabase/tests/20_who_said_test.sql`; `00_schema_test.sql` lists the table and pack.

Spill or Skip: no new table. pgTAP: `supabase/tests/21_spill_or_skip_test.sql`.

Party Mode: the column sits on `rooms`, which keeps its RLS; the screen reads through the API with the token, never Supabase directly. pgTAP: `supabase/tests/22_party_mode_test.sql`.

Live reactions: no table. pgTAP: `supabase/tests/23_reactions_test.sql`.

Daily Spill RLS: `daily_answers` has row level security and no policies; anon and authenticated have no grants. pgTAP: `supabase/tests/24_daily_spill_test.sql`; `00_schema_test.sql` lists the table.

Crews RLS: each table has one select policy for members (`is_crew_member`, security definer, so policies do not recurse); anon has no access; inserts only through the API. pgTAP: `supabase/tests/25_crews_test.sql` (including a member sees the crew and an outsider does not); `00_schema_test.sql` lists the tables. Privacy: `crew_rounds` keeps the points of everyone who played a round with the crew; the season table counts members only, and only members can read the history.

Custom packs: hidden packs are invisible to players and anon under the existing `packs_select` and `questions_select` policies, so a room's questions never leave it; the API reads them for members. pgTAP: `supabase/tests/26_custom_packs_test.sql` (own pack plays, another room cannot, hidden, deleted with the room).

Incident (2026-10-25, staging only): 3000 was pushed to staging before its code reached preview. Its foreign key gave PostgREST a second path between rooms and packs, preview's `packs(*)` embed became ambiguous, and every room load returned 500 (players saw the loading error screen). 3100 fixed it within minutes; code now names the link (`packs!rooms_pack_id_fkey`). Production was never affected.

Local packs: content only, under the existing pack RLS. pgTAP: `supabase/tests/27_local_packs_test.sql`; `00_schema_test.sql` lists eighteen live packs.

Premium packs: a column on `packs` under the existing RLS. pgTAP: `supabase/tests/28_premium_packs_test.sql`.

Achievements RLS: `player_stats` has row level security with one select policy, a player reads only their own row; anon has no access; writes only through the API (service role). `record_round_stats` is security definer and executable by service_role only. pgTAP: `supabase/tests/29_achievements_test.sql`; `00_schema_test.sql` lists the table. Privacy: stats hold counts only, never answers, and stay with the device session.

Series: a column on `rooms` under the existing RLS. pgTAP: `supabase/tests/30_series_test.sql`.

Nudge cooldown: a column on `players` under the existing RLS; `nudge` stays security definer and service_role only. pgTAP: `supabase/tests/31_nudge_cooldown_test.sql`.

# Migrations

Database changes made for the fix handoff (docs/SPIL_Fix_Handoff.md). Supabase CLI migrations
only run forward, so every migration has an undo script in `supabase/rollbacks/`. To undo one:
run its rollback script against the database, then mark the migration reverted so the CLI stops
counting it:

```bash
supabase migration repair --status reverted <version>
```

Apply order: staging first (`supabase db push` while linked to `cambebifktqgnbthumzq`), then
production when the release goes to `main`.

RLS: `players.age_band` is not in the column grants, so clients can neither read nor write it (pgTAP `07_age_bands_test.sql`); only the API writes it. Seed: adult packs get `min_age` 18.

SPIL-11: clients cannot update `rooms` (pgTAP `11_reveal_pacing_test.sql` checks `reveal_index`); only the host's API call moves the reveal.

SPIL-09: the new guess columns follow the existing `guesses` policies (a player reads their own guesses, everyone in the room after the reveal); pgTAP `10_guess_points_test.sql`.

SPIL-05: `captcha_events` has RLS and no grants for anon or authenticated (pgTAP `09_captcha_events_test.sql`).

SPIL-08: packs and questions keep their existing RLS (admin writes by role, public reads of live content); pgTAP `08_pack_sections_test.sql`; the seed sets sections, spice and 10 questions per game.

SPIL-03 RLS: the new columns sit on `players`, which already has row level security; members read them
through the existing policies. pgTAP: `supabase/tests/06_answer_progress_test.sql`. Seed: no
change needed (the columns have defaults).

Game modes RLS: `mode_inputs` has row level security; a player reads their own rows, and every member reads the room's rows once it is revealed. Writes go through `save_mode_inputs` (service role). pgTAP: `supabase/tests/13_game_modes_test.sql`.

Hot Takes: no new table; packs and questions keep their RLS. pgTAP: `supabase/tests/14_hot_takes_test.sql`; `00_schema_test.sql` lists Hot Takes among the live packs.

Most Likely To: no new table; votes are `mode_inputs` rows of kind `vote` under the existing RLS (a player reads only their own until the reveal; the reveal state sends counts, never who voted for whom). pgTAP: `supabase/tests/15_most_likely_test.sql`.

Red Flag, Green Flag: no new table or function; swipes are ordinary answers under the existing RLS. pgTAP: `supabase/tests/16_red_green_test.sql`.
